# 평가 리포트 — 완성 예시 (강사, 10/8 실측)

> 6회차 선택 과제(`docs/eval_report.md`)의 완성 예시입니다. 세 묶음, 다섯 줄이면 됩니다. 숫자는 10/8 수업 폴더(49건) 실측이고, 유형별 숫자는 방향만 읽습니다(유형 안에서 한 문항이 12~50%p).

기준 파일: `results/compare.csv` · `results/judge_calibration.json` · `results/calc_e2e.json` (2026-10-08)

## 1. 3단계 표에서 유형별로 (3줄)

| 지표 | baseline | hybrid | agentic |
|---|---|---|---|
| Recall@5 | 75.0% | 77.5% | 80.0% |
| MRR | 0.542 | 0.681 | 0.684 |
| 답변률 / 오거절률 / 미답변 정확도 | — | — | 90.0% / 10.5% / 100.0% |
| 문항당 시간 / 비용 | 2.6초 / 0 | 10.7초 / 0 | 17.3초 / 8.5원 |

1. **메타데이터형이 5회차에서 올랐다** (Recall@5 60% → 60% → 100%). 2013년 판과 현행 판을 가르는 것은 필터뿐이라, Self-Query 가 들어온 회차에 오른 것이 맞다. 유사상품비교형도 같은 회차에 66.7% → 100%.
2. **계산형은 4회차에서 올랐다** (40% → 80% → 80%). 계산 질문은 구간표가 든 청크를 찾아야 하는데 리랭커가 그것을 위로 올렸다. 5회차 계산 Tool 은 찾은 뒤의 일이라 Recall 에는 안 보인다.
3. **조항번호형과 복합형은 거꾸로 갔다** (100% → 87.5% → 75%, 100% → 100% → 60%). 조항번호형은 BM25 가 올려야 할 유형인데 이 코퍼스에서는 Dense 가 이미 다 찾고 있었고, 그 뒤에 필터가 들어오면서 발행사가 없는 표준약관 두 문항(S04 예금거래기본약관 제12조, S05 여신거래기본약관 제4조의2)을 잃었다. 복합형은 분쟁조정사례를 `특약`으로 뽑아 사례 문서를 잘라 낸 S28 이 빠졌다. **다음 할 일: 발행사가 없는 문서(표준약관·법령)에서 `issuer` 를 비우게 Self-Query 프롬프트에 한 줄.**

## 2. judge 가 사람과 어긋난 문항 하나

일치도(n=17): 완전 일치 29% · ±1 이내 59% · MAE 1.35 · judge − 사람 -1.12. 항목별 완전 일치: 근거 일치 88% · 수치·단위 82% · 근거 밖 주장 없음 35%.

**S01 (하나카드 제31조 리볼빙 정의).** judge 2/6, 사람 6/6. 답변이 정의를 맞게 말한 뒤 "약정결제비율은 10~100% 범위, 최소결제비율 10% 이상"을 덧붙였는데, judge 는 이것을 "질문 범위 밖의 추가 주장"으로 보아 근거 밖 주장 없음에 0 을 줬다. 그 문장은 인용한 제31조 청크 안에 있다. 루브릭의 0 은 "문서에 없는 사실 진술"인데 judge 가 "질문이 안 물은 것"으로 읽었다. **이 judge 는 "근거 밖"과 "질문 밖"을 구분하지 못한다.** 고치려면 루브릭 그 줄에 "인용한 청크 안의 내용이면 질문 밖이어도 2" 를 넣고 일치도를 다시 잰다.

## 3. 계산이 틀린 문항 하나

계산 정확도(E2E): 15문항 중 8 (53%). 5회차 골든 테스트는 32/32 — 함수는 맞고 틀린 것은 전부 앞 단계다.

**C07 (iM뱅크 가계대출 1억 2천만원, 약정 5% + 가산 3%, 월이자 50만원 2개월 연체).** 기대 803,333원, 결과 "계산 안 함". 판정 sufficient, 재검색 0회, Tool `delinquency_interest` 는 골랐다. 그런데 함수가 받지 않았다. `abstain_reason` 이 "파라미터가 맞지 않습니다: delinquency_interest() got an unexpected keyword argument 'amount'" — 함수는 `principal` 을 받는데 모델이 `amount` 라는 이름으로 넘겼다. **추출 단계의 이름 오류.** 답변에는 803,333원이 적혀 있지만 그것은 설명서에 인쇄된 예시를 인용한 것이지 함수가 만든 값이 아니다(계산 줄이 "안 함"). 고치려면 `calc_specs.yaml` 의 `from_question` 설명에 파라미터 이름을 예시와 함께 적거나, `calc_node._call` 이 함수 시그니처에 없는 이름을 버리고 `required` 가 비었다고 알리게 한다.

같은 15문항을 두 번 돌리면 결과가 흔들린다. C09(삼성화재 중도상환)는 첫 실행에서 잔여 기간을 2년으로 뽑아 400,000원(오답), 두 번째 실행에서 1년으로 뽑아 200,000원(정답)이었다. 추출도 실행 간 변동이 있으므로 계산 정확도도 범위로 말한다(6~8/15).
